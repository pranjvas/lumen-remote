## Lumen Remote — final research synthesis for a browser-hosted Samsung QA55Q95T remote + dashboard (2026-10-21)

Lead-architect synthesis merging the 9 area reports, their adversarial verdicts (a refuted verdict is replaced by its corrected claim), the previous synthesis, and the 6 gap answers. No TV contact was made while writing this; every live fact comes from read-only probes earlier today.

### 0. Headline conclusions
1. A fully local remote works today over three channels already proven on this TV: the paired WebSocket remote channel (wss 8002), REST (8001), and UPnP DMR (9197).
2. Live volume/mute is verified end to end. A 60-minute passive GENA session (12:10–13:10Z) received 14 change NOTIFYs (SEQ 1–14) on one SID, each 20–750 ms before the 1 Hz poll saw the change; a VOL+ hold produced one event per step. Push is primary; polling becomes a 30 s safety net.
3. Real picture values are reachable locally. TCP 1516 is OPEN today (1515 refuses); TLS 1.2 completes with Node 22 defaults; server `Samsung IP Control Server/1.0`, cert CN `Samsung IP Control G2`. One supervised `createAccessToken` (on-screen Allow) remains. Samsung's 2020 IP list maps menu "Brightness" → `backlightControl` (0–50) and menu "Shadow Detail" → `getVideoStates.brightness` (−5..5). No 2020 field report yet prints a real backlight value.
4. A second on-TV read path with PUSH likely exists: the Settings menu reads picture numbers from the system D-Bus service `org.tizen.tv.avoc` (daemon `avocd`). `GetBacklight(1)` returns the 2020 "Brightness"; signals `BacklightValueChanged`, `ContrastChanged`, `AvPictureModeChanged`, etc. are emitted. The Lumen Agent Node service could speak D-Bus over `/var/run/dbus/system_bus_socket`. Needs one supervised read-only probe; the emulator image shows no access check, but real firmware may ship a D-Bus policy.
5. The Lumen Agent (`lumenrmt01`) is installed and its UI app stays resident while hidden (51–83 min observed). The service's lifetime is only measured to 2.4 s; treat the companion as an on-demand probe until a heartbeat build measures it. The service context lacks all TV APIs (confirmed by static analysis of the 5.5 image's extension whitelist); only the UI context has `tvaudiocontrol`/`tvwindow`/`productinfo`.
6. MobileBFF (`mobilebff` 1.0.49, running) is an optional provider over the paired MSF link: quick-settings names, external-source names, app tiles/icons, and vconf reads with change pushes. It CANNOT give backlight/contrast (those are in AVOC, not vconf). Unprobed (WebSockets were barred during research).
7. SmartThings is optional, cloud-only, has no picture levels, and Samsung announced paid tiers from Oct 2026. Keep it secondary.
8. DISPLAY.brightness contradiction resolved: it is the generic Tizen setting `db/setting/Brightness` (default 100), always reads 1 (=100/100), and tracks nothing in the picture pipeline. Do not present it as backlight; no correlation run needed.

### 3. WebSocket remote channel (wss 8002)
Connect `wss://192.168.1.2:8002/api/v2/channels/samsung.remote.control?name=THVtZW4gUmVtb3Rl&token=<saved>` (name = base64("Lumen Remote"); send token only on 8002; 8001 returns unauthorized). TLS self-signed/private-CA; `ws` with `{rejectUnauthorized:false, perMessageDeflate:false, handshakeTimeout:10000}`. Pin the SHA-256 fingerprint via ws's `createConnection` hook in `secureConnect` BEFORE the token is sent (on 'upgrade' is too late); don't pin with `ca:<leaf>` (fails on G2 chains). Wait ~35 s for `ms.channel.connect`, ignoring early `ms.remote.touchEnable/touchDisable`, `ed.edenTV.update`, `ms.voiceApp.hide`. Prefer `data.token`; overwrite when it changes. Never open the socket as a probe (can wake the TV); connect only when REST says `PowerState=="on"`. Keep ONE persistent TV socket fanned out to browsers (the TV keeps its IME observer alive only while ≥1 remote client is connected, and never replays IME state to a late joiner). Keepalive: TV pings ~6 s; treat 12 s silence as dead; backoff 1/2/5/10/30 s ±20%.

Keys: `{"method":"ms.remote.control","params":{"Cmd":"Click|Press|Release","DataOfCmd":"KEY_*","Option":"false","TypeOfRemote":"SendRemoteKey"}}`. No ack; confirm via state. Spacing ≥200 ms taps, 300–500 ms macros. Holds are real TV long-presses (repeatable keys auto-repeat — 2 s VOLUP = +30 on a 2021 set; Back=Exit, REW/FF=track skip, Mute=Accessibility). KEY_POWER: Click only, never hold (~5 s soft-resets). Always send Release on pointerup/cancel/blur/visibilitychange/reconnect plus a 1.5 s-heartbeat / 8 s server watchdog. Server-side danger allowlist blocks KEY_FACTORY and service/ARC/panel/EXT keys. KEY_HDMI1-4 are no-ops; KEY_HDMI cycles. `ms.remote.numberpad`/`mbrlayout` are The-Wall-only (gated by `m_SupportWallProduct`); the browser draws its own 123/colour pad.

IME: send `SendInputString` (base64 UTF-8, replaces field; verify replace-vs-append) then `SendInputEnd`; optional `custom.remote.textReceived` broadcast. Receive `ms.remote.imeStart {data:type, entrylimit}` / `imeUpdate {data:base64}` / `imeDone {enable|disable}` (NOT a close signal) / `imeEnd` (closes). entrylimit −1 = unlimited. Decode via TextDecoder over atob. Mask password fields; never log imeUpdate. Native Tizen fields only (YouTube/Prime ignore it). Password path (unverified): HTTPS POST `:8002/remoteControl/imeInput/<b64>?token=`. Correction: `GET :8001/remoteControl/` returns 401 — it is remote-server's internal route, not a state API.

Pointer: `ProcessMouseDevice` Move (relative ~1920×1080) + LeftClick/RightClick, only after `touchEnable`; no scroll (use CH keys in browser).

Apps over the socket are unreliable on 2020 (`ed.*` silent; `ms.application.*` rejected on the remote channel) — use REST.

### 4. REST (8001 http / 8002 https)
`GET /api/v2/` → device info + PowerState (parse isSupport twice). `GET /api/v2/applications/<id>/` (trailing slash mandatory) → `{id,name,running,version,visible}`; only `visible` = foreground; `running` is noise (preloaded apps and hidden CineHD both report true). ~1.35 s/call, serialized — poll last-visible app + short list, 10–15 s timeouts. 404 for `org.tizen.*`/`com.samsung.*` aliases and for service apps (REST cannot see `*.MediaService`/`*.LumenService`). Launch: `POST …/<id>/` body `{}` → true; DELETE closes (unverified 2020); `POST /api/v2/webapplication/ {url}` opens a URL. Power semantics: only `"on"` = on; `"standby"` (observed today ~1 min after off) or `""` = standby; timeout = unknown (keep last); N consecutive connect failures = deep standby/off; ECONNREFUSED = stack up, not deep standby. 2020 T-series wake the network every 5–50 min, so reachability never means on.

### 5. UPnP/DLNA (9197)
SOAP getters via regex/entity parsing (no XML lib). GetVolume=4, GetMute=1 live; SetVolume/SetMute advertised (SetVolume used by HA/ollo69; SetMute unproven — use GetMute + KEY_MUTE). AVTransport = DLNA-cast media only (NO_MEDIA_PRESENT). **GENA verified live incl. change events** (section 0 #2): method is NOTIFY (not POST); TV grants the exact requested TIMEOUT (use 1800, never infinite); SEQ 0 initial event ~0.5 s; 14 SEQ≥1 change events; empty `<LastChange/>` clears must be ignored and deltas merged; the power-off self-mute is NOT evented (show Mute during standby as "TV off"); standby restart returns 412 (re-SUBSCRIBE). Inbound NOTIFY reached node.exe today. Still unverified: events while CineHD/Netflix are foreground, and HDMI-vs-TV sources. External-audio volume (ARC/optical/BT) tracks the TV-speaker path only — label it. Lifecycle rules in the architecture section.

### 6. DIAL (7678/8080) [live-tv]
`/nservice/` → `Application-URL: http://192.168.1.2:8080/ws/app/`. `/ws/app/<Name>` gives `<state>` (differs from REST `running`) in ~32 ms, `ACAO:*`. YouTube entry leaks a lounge `screenId` (secret) usable for YouTube now-playing. DIAL SCPD lists an undocumented `SendKeyCode`; never call without the user present.

### 7. IP Control (1516) and other picture-value read paths
7.1 **UPnP IPControlService (9110):** `urn:samsung.com:device:IPControlServer:1`; SCPD empty; GENA event feed carries only `IPControlState` (initial RUNNING, Content-Length 40, no propertyset). It is a discovery shell only — drop it as a data source. It does confirm the IP Control stack/module is present on this TV.
7.2 **Consumer IP Control JSON-RPC (1516), VERIFIED OPEN:** HTTPS `POST https://192.168.1.2:1516/` (any path, POST only; GET → 400). TLS 1.2 DHE-RSA, 1024-bit DH; Node 22 defaults work; Python needs `SECLEVEL=1`. Serialize (one connection; overlapping are reset). Prereq: enable *Settings > General > Network > Expert Settings > IP Remote* (and Power On with Mobile); pair once via `createAccessToken` (on-screen Allow, ~30–60 s; token persists; `-32011` = all slots taken). A params object with only `AccessToken` is a GET; any extra key makes it a SET.
  - Getters: `getTVStates` {inputSource, mute, pictureMode, pictureSize, soundMode, speakerSelect, volume}; `getVideoStates` {contrast, brightness(=Shadow Detail −5..5), sharpness 0-20, color 0-50, tint −15..15}; `backlightControl` {backlight 0-50} = menu "Brightness"; `colorToneControl` (Cool/Standard/Warm1/Warm2; a 2020 Q90T reads Warm2 live [community]).
  - Error latch rules (from the 2025 decompile): **-32001** Not supported model → latch UNSUPPORTED; **-32002** Failed → transient/mode-lock, never latch; **-32003** Invalid operation → latch only after ≥2 hits in normal viewing; **-32601** Method not found → never latch (Ambient/standby makes none-ambient methods answer -32601); **-32010** re-pair; **-32700** with token = stale token; **-32011** slots full. A 2018 set (1515) returns -32003 for backlightControl; 2024/25 Frames work; no 2020 backlight value is confirmed, so plan Brightness as LIVE from backlightControl but fall back to macro/TRACKED if it returns -32001 once or -32003 repeatedly.
7.3 **On-TV avocd D-Bus (candidate, strongest read path):** menu values come from `org.tizen.tv.avoc` / object `/org/tizen/tv/avoc` / iface `org.tizen.tv.avoc.AvOutputControl`. `GetBacklight(i type=1)→(i value,i ret)` is the 2020 "Brightness"; `GetBrightness`=Shadow Detail; plus GetContrast/GetSharpness/GetColorStrength/GetColorTint, GetPictureMode, GetGameMode, GetHdrType, GetLuxLevel, GetSoundMode, AvGetMasterVolume. Change signals (BacklightValueChanged, ContrastChanged, AvPictureModeChanged, GameModeChanged, …) fix the "changes from the physical remote" gap. Values live in `/opt/dbspace/.avoc.db`, NOT vconf. Implement a pure-JS D-Bus client in the Lumen service (EXTERNAL auth over the system bus socket) or a .NET companion calling `libavoc.so`. Privilege gating lives only in Samsung's C# wrappers (require partner-level `internal/default/platform`); the raw D-Bus service on the emulator has no cynara check and the socket is `SmackLabelIPIn=*`. Unproven on real firmware — one supervised probe required.
7.4 Hidden `webapis.avinfo.getBacklight/getBrightness/...` getters (in on-disk webapis.js, undocumented; native plugin/privilege unknown) and `libsettings-api` `settings_get_item_value` are secondary fallbacks. SmartThings `execute` is NOT a picture-level read path (null on 2025). `/sec/tv/showmenu {targetMenuId:'backlight', targetMenuParam:'30'}` and launching `org.tizen.menu` with extra `type=brightness` are write/anchor options (community, untested on 2020).

### 8. Other ports [live-tv/source-code]
8187 = the TV's own DLNA MediaServer control point (`libasfmediasharecp` ConfigureServers(8187,…)); any GET → 400/UPnPError 402; no device description, no Get* — not a MainTVAgent-style read source. 9080 = Netflix NRDP; `status=ok`; its Date header is TV-local time (IST) = a cheap TV clock. 9110 = IPControlService shell. 9119 = ScreenSharing (writes; redact MACs). 9999 = accepts TCP, non-HTTP binary protocol, owner unknown. 26101 = sdb (shared with CineHD pipeline; the remote server must not use it). 7676/55000/1515 closed (no MainTVAgent2/legacy channel/source read).

### 9. SmartThings (cloud, optional)
2020 TVs register as `VD-STV_2018_K`/`Samsung OCF TV`. Capabilities: switch, audioVolume/Mute, tvChannel, (samsungvd.)mediaInputSource, mediaPlayback/TrackControl, refresh, execute, custom.picturemode, custom.soundmode, custom.launchapp, samsungvd.ambient/remoteControl/firmwareVersion/supportsPowerOnByOcf. **No** backlight/contrast/eco (energyType is 2022+; lightControl is Hue Sync). Auth: PATs created after 2024-12-30 last 24 h → use an OAuth-In (API_ONLY) app (`smartthings apps:create`, scopes r:devices:* x:devices:* r:locations:*; localhost redirect can 403, use httpbin paste). Commands use the `{"commands":[{component,capability,command,arguments}]}` wrapper; COMPLETED ≠ applied (read back ~5 s later); 402 payment / 409 offline / 422 absent / 429 back off. Rate budget 12/min/device (conservative). Reads: `samsungvd.mediaInputSource.supportedInputSourcesMap` is the only source of friendly HDMI names; `tvChannel.tvChannelName` holds the foreground Tizen app id. Picture mode: send the display name, not the id. Power-on via `switch.on` needs Power On with Mobile + Wi-Fi + ONLINE. No free push (SSE/webhooks need a plan or public URL) — plan for polling.

### 10. On-TV companion (Lumen Agent, lumenrmt01)
Census settled: the Node SERVICE context has only tizen.{application, systeminfo, alarm, messageport, filesystem, package, datacontrol, time} + webapis.{preview} + a webapis stub (confirmed by the 5.5 image's `tizen-extensions-crosswalk-service` plugins.json). It has NO tvaudiocontrol/tvwindow/tvinfo/productinfo/network (those are UI-context PPAPI/`<embed>` plugins). UI context (foreground only — hidden UI JS is paused) has tvaudiocontrol (vol 4, muted, PCM), tvwindow (source TV 1; getVideoResolution errored), tvchannel (works despite being removed from docs — "Ace TV" 1927), hybridchannelinfo (current programme), tvinfo caption, systeminfo (BUILD, PANEL 3840×2160, VIDEOSOURCE), and getAppsInfo (406 apps incl. JioHotstar fiZNCxMH9Y.Hotstar, SonyLIV EUKHUxrGQA.SonyLIV, Airtel dY5YOOBTrj.airtelxstream, FanCode 0KIXYIdUgJ.FanCode). Transport: service dials OUT to the PC (http.request or pinned ws@4.1.0 + safe-buffer 5.1.2 + async-limiter 1.0.1; plain http/ws to avoid the 2016 root store); UI↔service via loopback HTTP (nonce path, reply 'armed' only after 'listening') or messageport. Lifecycle: termination hook is `onExit` (synchronous); no boot autostart on 2019+; `use.preview=bg_service` launches the service at power-on and every 10 min with a 5-min cap (experimental, untested sideloaded); re-arm from the PC via REST launch (flashes the UI). Guard Node 4's timer: `setTimeout(Infinity)` fires at ~1 ms — gate with `isFinite && <=2147483647`. Public privileges only; install/update needs sdb (coordinate with CineHD). Adds over LAN protocols: installed-app inventory + app-status push, VIDEOSOURCE/SOURCE_INFO, channel/programme, caption state, audio output codec, system health, firmware/panel — and, if the avocd probe succeeds, real picture values with push.

### 11. Picture/sound strategy
Source priority: IP Control (local, real values) ≈ avocd D-Bus (local, real values + push) > SmartThings (mode-level, cloud) > menu macro + TRACKED > Unavailable. Labels: LIVE, LIVE-SET (read back after write), POLLED, SMARTTHINGS·age, ON-TV APP, MACRO (warns "the TV menu will appear"), TRACKED·set hh:mm, ESTIMATED, SET-ONLY, UNAVAILABLE. Picture values are scoped per input × picture mode × SDR/HDR — invalidate the cache on any mode/input change, re-read after every write, and show -32002 as a "locked in this mode" badge. Macro engine: anchor from a verified point (toggle KEY_MENU, or deep-link `org.tizen.menu` with `type=brightness`), absolute routes (KEY_DOWN × index), "saturate-then-count" sliders, conservative timing (Up/Down 150 ms, Left/Right 75 ms, screen-change 800 ms, Return 300 ms); macros are visible and user-confirmed, values only TRACKED.

### 12. Power & WoL
Off: one KEY_POWER Click only when a fresh REST read says `on`, then block power sends 5–20 s (toggle + ~17 s REST lag). Never hold. On: if REST answers standby, KEY_POWER over the paired socket + WoL (Samsung says send both); else WoL (102-byte packet to directed broadcast + 255.255.255.255 + unicast, ports 9/7, from a socket bound to `socket.localAddress`, `setBroadcast` after bind; MAC = REST wifiMac, correct here because networkType is wireless); fallback SmartThings/IP Control within the ~1-min window. Poll REST 1–2 s up to 30 s. Prereq: Power On with Mobile. Windows strong-host: bind the UDP socket to the LAN address or it may leave via a VPN/virtual adapter.

### 13–15. Inputs / channels / now-playing / apps
No local read of input over REST/UPnP (7676 closed, 9110 SCPD empty). Read input via IP Control `getTVStates.inputSource`, companion VIDEOSOURCE/SOURCE_INFO + tvwindow.getSource, or SmartThings. Switch via IP Control `inputSourceControl`, SmartThings `setInputSource`, companion `tvwindow.setSource` + launch `org.tizen.tv-viewer`, or an anchored KEY_SOURCE macro (KEY_HDMI1-4 are no-ops). Channel keys reach the tuner; an HDMI STB only responds through Anynet+/CEC passthrough. Now-playing: REST `visible` for the app; companion tvchannel/hybridchannelinfo for tuner/TV-Plus; YouTube Lounge (DIAL screenId → loungeToken → bind long-poll) for YouTube; DLNA AVTransport for cast media; CineHD can self-report. App table (installed, live): CineHD pvcinehd01.CineHDTV 0.17.421; Lumen Agent lumenrmt01.LumenAgent 0.1.0; Netflix 3201907018807; YouTube 111299001912 (also 9Ur5IzDKqV.TizenYouTube); Prime 3201910019365; Apple TV 3201807016597; Apple Music 3201908019041; Spotify 3201606009684; Plex 3201512006963; Internet 3201907018784; SmartThings 3201910019378; Gallery 3201710015037; Amazon Alexa 3202004020626; Samsung Promotion 3201807016658; plus Tizen-only JioHotstar/SonyLIV/Airtel Xstream/FanCode/Hot IPTV/Smart IPTV from the 406-app census. Not installed (404): Disney+, ZEE5, Tubi, Twitch, Xbox, Luna, Viu, iQIYI, etc. Icons: no TV HTTP endpoint and `ed.apps.icon` is silent on 2020 — bundle curated icons or read companion iconPath.

### 16. Prior-art UX and hosting
Prior art: tedyno/tvremote, Couch Remote (UPnP volume slider), Clicky (honest "what Samsung doesn't expose"), Tele (fixed instrument), HA universal-remote-card (hold 500/repeat 100/double-tap 200/swipe 16 px; slider ignores updates while dragging and 1000 ms after). Design language "Halo": dark-first instrument (Nocturne) + warm light (Gallery), one Ember accent replaced by a contrast-clamped OKLCH tint of the foreground app icon, a luminous volume halo ring, self-hosted Inter/Fraunces/JetBrains Mono (SIL OFL), inline SVG sprite, a provenance badge on every value. Hosting: Node 22 + only `ws`; UI on 127.0.0.1 with Host-allowlist (421), Origin check (403), CSRF header, static in-memory map, CSP `default-src 'self'`; a separate LAN-bound GENA listener accepting only NOTIFY from 192.168.1.2 on a secret path; phone access opt-in with PIN/QR; autostart via a Startup-folder `wscript.exe //B` JScript launcher; a fork supervisor (exit 0 stop / 75 restart / else backoff); the port is the single-instance lock; tokens in gitignored `data/tv.json` or `%LOCALAPPDATA%`, DPAPI optional. Windows Firewall: a cancelled or non-admin prompt creates permanent node.exe block rules; bind the LAN listener only when the user enables live events/phone access, and detect success by whether NOTIFYs arrive.
